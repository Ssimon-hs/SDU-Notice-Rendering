# 一键山大：v0.5 技术架构

## 运行形态

```text
浏览器工作台（React + Vite）
  生产：后端直接托管 dist（8765）
  开发：vite dev server（5173）+ /api 代理
          │
          ▼
FastAPI 本地接口（server/main.py，控制器层）
          │
          ▼
业务服务层（server/services.py）
  筛选 / 搜索 / 关联 / 校历 / 推荐数据
          │
          ▼
结构化抽取（server/classifier.py）  抓取层（server/sources/*）
  分类、通知新闻判定、适用对象、      主站 / 官方站点 / 目录自动发现
  8 类时间、材料与步骤
          │
          ▼
本地存储（server/store.py）
  data/notices.json · source_status.json · custom_sources.json · backups/
```

分层约束：控制器只解析参数与封装响应；服务层不依赖 HTTP 类型；抓取层每个来源独立失败隔离。

## 模块边界

1. **sources**：`common`（HTTP 与正文抽取）、`sdu_main`（主站）、`official_sites`（内置站点）、`discovery`（官方目录自动发现）。每个来源自动发现栏目、翻页、读正文与附件，独立报告成功 / 失败原因。
2. **classifier**：基于标题 + 正文的结构化抽取，多标签分类、通知 / 新闻 / 公示结果判定、适用对象、8 类时间节点、材料与步骤。抽取不到就留空，不编造。
3. **store**：JSON 文件读写（原子替换）、来源状态、自定义源、反馈、自动备份（保留最近 5 份）。
4. **services**：筛选 14 项条件、全文搜索（含自然语言提问与错别字纠正）、同组活动关联、校历事件聚合。
5. **前端 lib**：`api`（类型化 fetch、4xx 不重试 5xx 重试、错误中文映射）、`store`（localStorage 画像 / 收藏 / 待办 / 设置）、`i18n`（中英）、`recommend`（打分 + 破茧）、`utils`（日期、ics 导出）。
6. **前端 pages**：引导、首页、推荐、全部通知、搜索、正文、待办、收藏、校历、社区、来源、设置。
7. **AI 提供方**：配置入口已就绪（OpenAI 兼容 / DeepSeek / 通义 / Ollama / 自定义），调用端待接入；当前使用本地规则整理并如实标注。

## 核心数据对象

- `Notice`：官方原标题、发布单位、发布时间、8 类时间节点、截止时间、分类（多标签）、性质（通知 / 新闻 / 公示结果 / 待分类）、适用对象、材料、步骤、正文、附件、图片、关联 id、状态。
- `SourceStatus`：来源 id、名称、状态（ok / failed / unknown）、抓取数量、最后更新时间、失败原因。
- `Profile`：身份、学院、专业、年级、校区、研究方向、兴趣、目标、关键词、屏蔽词、提醒偏好、昵称。
- `Todo`：通知 id、标题、截止、状态（未开始 / 进行中 / 已提交等待结果 / 已完成）、提醒、备注、子任务、材料勾选。
- `Favorite`：文件夹、标签、备注、快照（标题 / 来源 / 时间 / 链接），不自动创建待办。

## 关键约定

- 标题一律使用官方原标题，不拼接日期、栏目或摘要。
- 截止时间早于发布时间的解析结果直接丢弃，不误导用户。
- 已截止内容只保留元数据与官方链接，不混入当前结果；用户主动搜索历届时才出现。
- 抓取失败必须给出具体原因（需要登录、证书异常、站点失效、栏目改版、解析失败）。
- 未完成的功能一律显示「暂未开放」，不做假按钮。
- 所有用户数据保存在本机，不登录、不同步、不上传。
